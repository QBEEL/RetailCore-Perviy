# RetailCore

RetailCore — приложение нового поколения для категорийных менеджеров и специалистов по управлению ассортиментом.

Система помогает автоматизировать ежедневные задачи:
- анализ товарных каталогов;
- поиск и сравнение товаров;
- сопоставление ассортимента разных брендов;
- выявление аналогичных продуктов;
- настройка параметров поиска под различные категории;
- подготовка данных для принятия закупочных решений.

RetailCore создан для того, чтобы сократить время на рутинный анализ и повысить эффективность работы с ассортиментом.

Технически это настольное приложение для Windows: берёт данные из
файла-каталога (артикул, EAN, цена) и проставляет их в целевую таблицу,
сопоставляя строки по идентификаторам, названию и объёму. Работает с любыми
брендами и любой структурой колонок — роли полей определяются автоматически
по заголовкам и содержимому файла.

> Проект раньше назывался Excel Data Matcher. При первом запуске новой версии
> настройки, история и журналы автоматически переезжают из
> `%APPDATA%\ExcelDataMatcher` в `%APPDATA%\RetailCore` — делать ничего не нужно.

## Запуск

**Готовое приложение:** `dist\RetailCore.exe` — один файл, Python и
библиотеки не нужны. Скопируйте его куда угодно и запускайте двойным кликом.

**Из исходников:** двойной клик по `start.bat`. При первом запуске создаётся
окружение `.venv` и устанавливаются зависимости (несколько минут). Ручной
запуск: `.venv\Scripts\python.exe run.py`

## Сборка

```
.venv\Scripts\python.exe tools\make_icon.py                 # иконка из app.svg
.venv\Scripts\pyinstaller.exe RetailCore.spec --noconfirm --clean
```

Проверка собранного файла без открытия окна — отчёт пишется в указанный файл:

```
"dist\RetailCore.exe" --selftest каталог.xlsx цель.xlsx отчёт.txt
```

## Возможности

**Сопоставление.** Этапы по убыванию надёжности: артикул → EAN → название с
объёмом → нечёткое сравнение названий. Объём проверяется как жёсткое условие с
допуском 5 %, поэтому строка на 50 мл не получит цену варианта на 10 мл.
Спорные случаи попадают в «Требует проверки» со списком вариантов вместо
молчаливой подстановки.

**Несколько каталогов.** Кроме основного прайса можно добавить дополнительные —
архивные за прошлые месяцы или прайсы других каналов. Каждый этап проходит по
всем каталогам сразу; при равной оценке побеждает тот, что выше в списке.
Колонка «Каталог» показывает, откуда взяты данные. Это закрывает позиции,
которых нет в текущем прайсе, — источником остаются ваши собственные файлы, а
не сторонние данные.

**Перенос заказа** (вкладка «Заказ»). Количества из выгрузки 1С переносятся в
бланк заказа поставщика. Лист и колонка определяются автоматически: из
нескольких колонок «Заказ» берётся та, где действительно есть числа
(в 1С такая колонка есть у каждого магазина). Оба выбора меняются вручную —
в книге с несколькими листами нужный указывается в списке «Лист», и этот выбор
запоминается для файла. Соответствие ищется по артикулу, затем по штрихкоду;
совпадение по названию автоматически не применяется — в бланке рядом стоят
обычная позиция и ТЕСТЕР, у которых артикулы отличаются одной буквой.

Колонка «Характеристика» из выгрузки 1С показывается рядом с наименованием и
участвует в подборе: у оттенков 01 и 02 название одинаковое, различает их именно
она.

Позиции, которых нет в бланке, показываются отдельным списком с похожими
строками (тестеры помечены) и выгружаются в отдельный файл. Нужную строку можно
найти поиском по всему бланку — по артикулу, штрихкоду, словам названия или с
опечаткой.

**Новинки и хиты.** После переноса приложение сообщает, сколько в прайсе позиций
с пометками поставщика — НОВИНКА, ХИТ, NEW, HIT, ЛИМИТКА, LIMITED — которых нет
в заказе. По кнопке «Новинки и хиты» открывается список: укажите количество, и
позиции добавятся в заказ и запишутся в бланк вместе с остальными. Пометка
ищется отдельными словами по всей строке прайса, поэтому «Новый артикул» и
«силиконовый» новинками не считаются.

**Исключения.** Номенклатура 1С и прайс поставщика описывают товар по-разному:
«Диффузор для ароматерапии Z&R Ветивер, Лимон» против «Диффузор. Средство для
ароматизации помещений Ветивер, Лимон (212,5мл)». Ручная привязка сохраняется
как исключение и применяется при следующих переносах раньше автоматического
подбора. Исключение хранит артикул, штрихкод и название, а не номер строки,
поэтому переживает новый бланк с другим порядком строк. Список правится по
кнопке «Исключения».

**Поиск.** Частичные совпадения, любой регистр, лишние пробелы, поиск сразу по
нескольким словам и опечатки (rapidfuzz). Каждый результат получает оценку
Match Score с учётом веса поля: артикул важнее названия, название важнее
описания. Поля для поиска и их веса настраиваются.

**Таблицы.** Сортировка, фильтр по статусу, поиск с подсветкой совпадений,
изменение и скрытие колонок, копирование в буфер как TSV (Ctrl+C),
двойной клик — карточка товара.

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+1` … `Ctrl+5` | Сопоставление / Заказ / Каталог / История данных / Настройки |
| `Ctrl+O` / `Ctrl+Shift+O` | Выбрать каталог / целевой файл |
| `Ctrl+R` | Открыть файлы прошлой сессии |
| `F5` | Запустить сопоставление |
| `Ctrl+S` | Сохранить результат |
| `Ctrl+F` | Поиск |
| `Ctrl+C` | Копировать выделение |

## Структура

```
run.py                    точка входа (её же собирает PyInstaller)
RetailCore.spec           параметры сборки .exe
app/
  core/        логика: модели, нормализация, схема, чтение Excel, поиск, сопоставление
  core/snapshots/  история данных: схема БД, хранилище снимков, сравнение версий
  ui/          интерфейс: страницы, виджеты, тема, фоновые задачи
  ui/assets/   иконки: app.svg — исходник, app.ico — иконка приложения
tools/         make_icon.py — пересборка иконки из SVG
tests/         тесты ядра (pytest)
legacy/        первая версия приложения на tkinter
dist/          собранное приложение
```

Слой `core` не зависит от интерфейса и покрыт тестами:

```
.venv\Scripts\python.exe -m pytest tests -q
```

## История данных

Каждая загрузка каталога сохраняется целиком в локальную базу
`%APPDATA%\RetailCore\snapshots.db`, поэтому состояние ассортимента и цен
на любую прошлую дату остаётся доступным: можно сравнить прайс за август с
прайсом за сентябрь, увидеть, какие позиции появились и на сколько выросли
цены. Снимок делается сам, в фоне, ничего нажимать не нужно.

Снимаются только каталоги — на страницах «Сопоставление» (основной и
дополнительные прайсы) и «Каталог». Целевой файл и бланк заказа не снимаются:
это то, что заполняется, а не источник данных.

Повторная загрузка того же файла новую версию не создаёт — версии различаются
по содержимому (SHA256), а не по имени или времени. Изменился файл — появился
новый снимок.

На вкладке **«История данных»** (`Ctrl+4`):

| Действие | Что делает |
|---|---|
| Открыть | Состояние каталога на выбранную дату, с поиском |
| Сравнить версии | Новые и удалённые позиции, изменение цен и характеристик |
| Удалить | Убирает снимок после подтверждения и освобождает место на диске |

Каталог на 100 000 товаров занимает около 28 МБ и записывается примерно за
секунду. Автоматической чистки нет: история нужна за годы, поэтому снимки
удаляются только вручную. Отключить сохранение можно в «Настройках» →
«История данных», там же показан текущий размер базы.

Ход импорта пишется в `%APPDATA%\RetailCore\snapshot.log`.

## Обновления

Приложение само проверяет новую версию на GitHub Releases при каждом запуске
и предлагает обновиться — категорийным менеджерам не нужно ничего скачивать
вручную. Настройки поведения — на странице «Настройки» → «Обновления»
(проверять автоматически, загружать автоматически, показывать список
изменений); журнал — `%APPDATA%\RetailCore\update.log`.

Релизы берутся из [QBEEL/RetailCore-Perviy](https://github.com/QBEEL/RetailCore-Perviy)
— репозиторий задан в [app/ui/update_check.py](app/ui/update_check.py) и должен
оставаться публичным: проверка идёт без токена, а приватный репозиторий
потребовал бы встраивать токен в exe, раздаваемый пользователям, откуда его
несложно извлечь.

**Публикация новой версии:**

1. В [app/__init__.py](app/__init__.py) поднимите `__version__` (semver:
   `MAJOR.MINOR.PATCH`).
2. Соберите exe: `.venv\Scripts\pyinstaller.exe RetailCore.spec --noconfirm --clean`.
3. Посчитайте контрольную сумму:
   ```
   certutil -hashfile "dist\RetailCore.exe" SHA256
   ```
4. Создайте `version.json` (не путать с `__version__` в коде — это отдельный
   файл, который публикуется только на GitHub, в репозитории его нет):
   ```json
   {
     "mandatory": false,
     "sha256": "<хеш из шага 3>",
     "changelog": ["Что изменилось", "Ещё один пункт"]
   }
   ```
   `mandatory: true` не даёт пропустить версию или отложить обновление —
   используйте только для критичных исправлений.
5. На GitHub: **Releases → Draft a new release**, тег `vX.Y.Z` (например,
   `v2.1.0`, обязательно с `v`), к релизу приложите два файла:
   `RetailCore.exe` и `version.json`. Заголовок и описание релиза —
   произвольные, приложение их не читает (текст «Что нового» берётся из
   `changelog` в `version.json`).
6. Опубликуйте релиз. Проверьте на тестовой машине со старой версией: при
   запуске должно появиться уведомление о версии `X.Y.Z`.

## Настройки

Хранятся в `%APPDATA%\RetailCore\settings.json`: выбранные поля поиска и
их веса, пороги, размеры окна, недавние файлы, ручные правки ролей колонок,
выбранные листы, исключения переноса, настройки автообновления и истории
данных. Сохраняются автоматически.

В той же папке лежат история данных (`snapshots.db`) и журналы `update.log`
и `snapshot.log`. Открыть её можно кнопкой в «Настройках» → «История данных».
